# Addresses

> Source: `include/inc_module/mod_addresses/`

The addresses module manages address and contact records in the backend and renders them on the frontend through a filterable address locator. Module registration (`module.default.php`): `$_module_name = 'phpwcms_addresses'`, `$_module_type = 1` (backend only), no content part, frontend render hook.

## Storage

> Source: `backend.default.php`

Records live in the shared contact-detail table `phpwcms_userdetail`, scoped by `detail_regkey = 'PHPWCMS-ADDRESS'` (module constant `MODULE_KEY`). Deletion is a soft delete (`detail_aktiv = 9`); verify toggles the same flag. The table holds generic `detail_*` columns (`detail_text1–3`, `detail_varchar1–4`, `detail_float1–2`, `detail_int1–2`), which the module maps to its fields.

## Backend

Available to usergroups with the addresses module enabled. URL: `phpwcms.php?do=modules&module=phpwcms_addresses`. The routing (GET parameters `edit`, `verify`, `delete`, else listing) lives in `backend.default.php`.

### Entry form

> Source: `backend.editform.php`, `inc/processing.inc.php`

| Field | Type | Default | Description |
| ----- | ---- | ------- | ----------- |
| Representation office | checkbox | off | Marks the entry as a representative office (`detail_varchar2`, CHECK) |
| Company | text | – | Company OR last name is mandatory |
| Location | text | – | Stored in `detail_varchar4` |
| Title / First name / Last name | text | – | Person fields |
| Street / Addition / City / Zip / Region | text | – | Postal address fields |
| Country | select | DE | Country list from `getCountry()` |
| Also for | multi-checkbox | – | Additional countries the entry appears under (stored as text) |
| Fon / Fax / Mobile / Website / Email | text | – | Contact fields; email format is validated |
| Language | select | – | `DE`, `EN` |
| Files | file list | – | Attached files with descriptions, stored as JSON in `detail_text3` |
| Annotation | textarea | – | Free text (`detail_text1`) |
| Zip-code area | text | – | Locator grouping value (`detail_varchar3`) |
| Latitude / Longitude | number | – | Geocoordinates (`detail_float1`, `detail_float2`) |
| Sort | number | 0 | Ordering (`detail_int2`) |
| Public | checkbox | off | Only public entries appear in the frontend locator |
| Active | checkbox | on | Record state |

When lat/long are empty, the edit form can fill them by geocoding the postal address against the Nominatim service; a Google Maps link to the coordinates is shown alongside (`backend.editform.php`). There is no CSV import or export, and no coupling to the frontend login (`template/inc_script/felogin/` does not read address records).

### Listing

`backend.listing.php` shows company and name, city, country and status, ordered by company, city, country. Actions: edit, verify, delete.

## Frontend

> Source: `frontend.render.php`, `inc/search.addresses.php`

The render hook replaces `{PHPWCMS-ADDRESS-LOCATOR}` with the locator. It queries public, active records with the `PHPWCMS-ADDRESS` regkey, left joins `phpwcms_country` on the country code, and sorts by sort value, zip and company.

The locator UI is generated by `inc/search.addresses.php` — it is not template driven. It exposes filters for continent, country, city, free text and zip (`continent_filter`, `country_filter`, `city_filter`, `filter`, `filter_zip` GET/POST parameters) and renders Bootstrap based cards; contact persons and attached files (rendered through the file list renderer of content part 7, `include/inc_front/content/cnt7.article.inc.php`) collapse inside each card. Map images ship in `include/inc_module/mod_addresses/template/` together with `js/GoogleMaps.js`; `frontend.init.php` stays empty.

## Configuration

The module registers no configuration keys. Backend access follows the module group in the usergroup editor — see [Modules overview](index.md).
