# phpwcms Development Guidelines

Welcome! This is the developer instructions file for **Antigravity CLI**. It provides project context, guidelines, environment setup, and commands.

## Product & Brand Rules
- **Product Name**: ALWAYS write the product name as **phpwcms** in all lowercase letters (e.g. in commits, documentation, changelogs, code comments). NEVER capitalize it as phpWCMS.
- **Git Branching**: The development branch (`v2-dev`) is the leading branch. Development changes should ONLY be merged forward into `master` or target legacy branches. NEVER merge `master` or release commits back into the development branch.

## Tech Stack & Environment
- **Backend**: PHP >= 8.2 (configured for PHP 8.2)
- **Local PHP CLI**: Always use `/Applications/MAMP/bin/php/php8.2.32/bin/php` instead of default system `php`.
- **Web Server Synchronization**: The development repository (`/Users/slackero/Dropbox/Development/phpwcms/phpwcms-dev`) is NOT the active Apache document root. Synchronize changes to `/Users/slackero/Sites/dev-phpwcms` via `make sync`. NEVER use `--delete` with rsync; files in `/filearchive/`, `content/images/`, and `content/tmp/` must never be deleted.
- **Database**: MySQL 5.5+ / MariaDB 10.4+
- **Dependency Management**: Composer (vendor directory at `include/vendor`)
- **Coding Standards & Analysis**: PHPStan Level 5 (100% clean, 0 errors across all 1,157 files)

## Core Commands
- **Sync to Test Server**: `make sync`
- **Run static analysis**: `make phpstan-analyse` (or `/Applications/MAMP/bin/php/php8.2.32/bin/php include/vendor/bin/phpstan analyse -c .phpstan/phpstan.neon --memory-limit 1G`)
- **Update PHPStan baseline**: `make phpstan-update`
- **Build assets**: `make minify`
- **Start Docker stack**: `make docker-up`
- **Stop Docker stack**: `make docker-down`
- **Install dependencies**: `composer install`
- **Update autoload maps**: `composer dump-autoload`
- **Standalone Upgrader / Migrations**: `/Applications/MAMP/bin/php/php8.2.32/bin/php setup/upgrade.php`
- **Update codebase map**: `make stacklit-update`

## Coding Style & Conventions
- **PHP Compatibility**: Maintain strict compatibility with PHP 8.2+. Always run `/Applications/MAMP/bin/php/php8.2.32/bin/php -l` to verify syntax.
- **Quotes**: Always use single quotes for PHP strings unless variable interpolation is required. Always use double quotes for HTML tag attributes.
- **Localization**:
  - In single-quoted translation strings with an apostrophe (e.g. French `d’images`), use the typographic apostrophe character `’` (U+2019) instead of an escaped backslash-quote `\'`.
  - When wrapping words in double quotes in language files, use the typographic quotes based on language rules (e.g. German `„Anmerkung“`).
  - Never duplicate English strings untranslated into another language file; `en` is always loaded first as the default fallback.
- **Database Safety**: Focus on parameterized queries and input sanitization to prevent SQL injection.
- **XSS Prevention**: Sanitize all dynamic HTML output.
- **Folders to Ignore**: Never explore, check, or scan inside `include/vendor/` or `node_modules/`.
